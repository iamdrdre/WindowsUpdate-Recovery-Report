# 典型小问题

## 下载100%、安装76%、DISM 3.8%不动，是否卡死？

下载与安装是不同阶段，百分比重新计算正常。安装或DISM的某个百分比停留也不足以证明挂死。本案 CBS 时间戳持续推进，DISM后来到达100%成功。先记录等待时间、最新日志时间和错误摘要，再判断；不要只凭百分比强制结束系统安装。

## 为什么PowerShell校验报路径不存在，复制却成功？

Cursor数据已由robocopy复制成功，但Windows PowerShell的Get-FileHash/Resolve-Path在深层长路径上报错。切换PowerShell 7后，全部校验通过才删除源目录。这支持长路径处理是当时的障碍，不意味着所有“路径不存在”都由长路径引起。

先用 `$PSVersionTable.PSVersion` 确认版本，通过独立启动的PowerShell 7重新复制/校验。原案例用的是应用随附的pwsh.exe路径；公开教程不应依赖该私人安装路径。其他机器可启动已安装的PowerShell 7；不要在PowerShell 5.1里假设换一条命令就自动变成7。

robocopy退出码0–7不属于其失败退出码范围，8及以上应停止；但0–7也不能替代逐文件内容验证。备份后源文件可能继续变化，应先退出应用，不通过校验就不删源。

## WPS的cache.db被占用怎么办？Word是WPS吗？

本案进程路径确认wps.exe属于WPS Office；微软Word通常运行WINWORD.EXE。两者都能打开DOCX，不能只凭扩展名判断。保存工作后正常退出对应窗口，再检查进程；不要复制历史PID去杀当前不明进程。

```powershell
Get-Process -Name WINWORD,wps -ErrorAction SilentlyContinue |
    Select-Object ProcessName,Id,Path
```

预期能识别当前程序；空结果表示此刻未找到这些进程，不代表其他后台组件一定退出。cache.db仍锁定时，应停止清理、保留源目录，不能跳过它继续删。清WPS用户数据并非卸载Word，但这些数据仍可能包含草稿与恢复记录。

## 我的电脑没有F盘，为什么命令显示F？

ISO挂载成虚拟DVD会分配可用盘符，本案先为F，后续也出现过G。它不代表多出实体硬盘，更不代表把Windows安装到该盘。ISO放D盘、从虚拟DVD启动向导、系统继续在C盘，三者是不同概念。

## 获取更新时取消后，为什么显示清理？

这是向导的取消收尾过程，应等它关闭。本案在腾出空间后的重试阶段遇到此现象；重新打开后选“不是现在”跳过在线动态更新检查，再核对保留文件和应用。它不修复空间不足，也不替代离线介质的兼容性检查。

## 日志有很多Error，是否每一个都要修？

不应只数Error。本案setupact明确记录空间需求、可用空间和失败返回0x80070070，优先处理这一已证实阻断点。其他Error需按时间和调用链评估，既不能全部当根因，也不能未经检查宣称无害。

## 为什么先0x800F0982，后来0x800F0991？

这是用户按顺序反馈的两个安装错误。后一个有明确CBS文件缺失和基线恢复失败记录，前一个缺少同等证据。不能仅凭错误码相近认定底层原因完全相同，也不应把代码变化当作修复成功。
