# 故障经过与证据

## 环境

- Windows 11 家庭中文版，22H2，构建版本 `22621.1778`（首次诊断时）。
- 更新长期无法完成；后续追查的代表性更新为 KB5043145。
- 该版本当时已经较旧；诊断期间记录其家庭版 22H2 支持周期已结束。应通过微软当前官方渠道选择受支持的升级版本。

## 阶段一：下载错误 `0x80004002`

Windows Update 日志出现以下连续错误链（时间与设备信息已删减）：

```text
DownloadManager *FAILED* [80070422] Connect to the DO service
DownloadManager Exit Code: 0x80246008, Extended Code: 0x80070422
DownloadManager *FAILED* [80004002] Method failed [CAgentDownloadManager::DownloadUpdate]
```

因此，`0x80004002` 并非这次下载问题最有用的根因线索。日志明确指出连接 Delivery Optimization（`DoSvc`）失败，`0x80070422` 表示相关服务被禁用。

配置快照进一步确认：

- `DoSvc`：启动类型 Disabled（注册表 `Start=4`），停止状态；服务键有 `WubLock=1`。
- `WaaSMedicSvc`：同样 Disabled，并有 `WubLock=1`。
- 两个服务注册表键的 ACL 只授予读取权限，常规管理员写入因此失败。
- `wuauserv` 为手动启动，但也有锁定标记；BITS 按需停止本身不是故障证据。
- 相关微软 DLL 的签名有效。

这些现象与更新屏蔽工具或脚本的配置相符，但没有证据能确认是哪一个工具、谁执行过、何时执行。日志保留范围也不足以证明问题从 2024 年起始终相同。

用户先备份服务配置和 ACL；常规 sc/reg 命令因只读权限被拒绝。随后仅暂时接管 DoSvc 根键，给 SYSTEM 与 Administrators 添加根键 FullControl，恢复原所有者，再以 reg.exe 将 Start 改为2。重启后 `sc.exe qc DoSvc` 显示延迟自动启动，`sc.exe query DoSvc` 显示 RUNNING；之后更新文件能够下载。完整命令、重写示例及回退见[命令流程](command-playbook.md)。

## 阶段二：安装错误从 `0x800F0982` 到 `0x800F0991`

KB5043145 下载完成后，用户先报告0x800F0982，后来重试出现0x800F0991。没有保留足够的前一错误上下文，不能证明两者一定来自完全相同的底层原因。后续 CBS 反复指向同一个组件文件缺失：

- 包：`Microsoft-Windows-WMIC-WOW64-Package` 的 `zh-CN` 资源。
- 组件：`Microsoft-Windows-WMPNSS-Service.Resources`。
- 文件：`wmpnetwk.mfl`，目标版本 `10.0.22621.2506`。
- CBS：`PSFX_E_MISSING_PAYLOAD_FILE`，增量/完整文件缺失，基线 hydration 校验失败。

这些记录定位了安装阶段的阻断点：所需组件文件无法取得、基线恢复失败。它们不能独立证明下载归档损坏，也不能确定最初造成缺失的操作。该问题与此前 DoSvc 下载错误发生在不同阶段。

DISM `/CheckHealth` 报告组件存储可修复。用户随后运行 DISM `/RestoreHealth` 和 `sfc /scannow`，两者分别报告操作成功、找到并修复损坏文件；但该 KB 后续仍出现 `0x800F0991`。因此不能把修复工具的成功输出等同于目标更新已成功。

## 阶段三：安装介质就地升级因空间不足回滚

用户使用微软安装介质，语言与版本选择为 Windows 11 家庭中文版，并选择保留个人文件和应用。第一次尝试失败：

```text
0x80070070 - 0x2000A
PREPARE_FIRST_BOOT / SAFE_OS
```

Panther `setupact.log` 给出了直接原因：

| 项目 | 字节 | 约合 GiB |
|---|---:|---:|
| 安装后续操作估算需求 | 13,976,164,622 | 13.02 |
| 当时可用空间 | 10,816,671,744 | 10.07 |
| 缺口 | 3,159,492,878 | 2.94 |

其他 Panther 错误（例如某些迁移插件、注册表清理或 PITR 文件提示）同时出现，但空间检查失败是有明确日志证据支持的阻断点。没有必要先对照每一条 `setuperr.log` 警告逐项修复。

用户之后反馈 C 盘剩余 40.6 GB，`D:\Windows.iso` 存在，并重新启动安装程序。新一轮截图显示最终确认页选择了“Windows 11 家庭中文版”以及“保留个人文件和应用”。此后用户明确回报系统已经更新成功。因此，本案最终状态更新为成功，成功依据为用户确认，更新后的具体构建号未采集。

## 空间释放过程（用户确认后执行）

用户选择保留应用、仅清理明确不需要的用户数据。操作前先复制到 D 盘，使用逐文件 SHA-256 校验，然后才删除 C 盘副本：

- Cursor `User` 数据：复制和哈希校验通过后清理；备份保留。
- 剪映 `User Data`：复制和哈希校验通过后清理；备份保留。
- WPS `wps` 用户数据：复制后，校验时 `cache.db` 正被 `wps.exe` 占用。**校验未通过/未完成时没有删除源目录。**

不要把这些操作理解成卸载应用，也不要把“用户数据”笼统等同于缓存。特别是 WPS 进程占用时必须先关闭应用，重新进行完整校验。

## 已完成与未确认

**已观察到：** 下载错误的服务原因、恢复 `DoSvc` 后下载恢复、KB 组件缺失错误、DISM/SFC报告修复、安装介质升级因空间不足回滚、腾挪空间后再次到达安装确认页。

**最终结果：** 用户确认系统更新成功。该结果不代表旧 KB5043145 必须被单独安装，也不证明所有更新相关服务权限、策略和任务都恢复为默认值。

**未采集：** 更新后的版本及构建号、后续多轮 Windows Update 检查记录、WPS 用户数据是否最终完成校验并清理。用户的成功回报可以确认本次结果，但不能保证未来永不再出现更新错误。
